# MIRA 3D 基本版（フォルダ読込）

2026-11-20から、`MIRA_3Dフォルダ読込版.html`と`folder_reader/`を今後の基本版とします。フォルダ内の測定ファイルを読み込み、番号差に応じた位置に3D表示します。旧固定データ版2つは`archive/`に保管します。

旧版はHTML・JS・CSS・ローカル生成データをまとめて移動しました。今後の機能追加は基本版に行い、アーカイブの表示処理は変更しません。[旧版一覧](archive/index.html)から開けます。

## 基本版の使い方

[MIRA_3Dフォルダ読込版.html](MIRA_3Dフォルダ読込版.html)をChromeまたはEdgeで開きます。追加ライブラリ、Pythonによる事前変換、サーバー起動は不要です。

1. 「フォルダを選ぶ」で測定ファイルを含むフォルダを選択する。
2. サブフォルダと系列（c・u・vなど）を選択する。別フォルダの同じ系列は自動で混ぜない。
3. 開始番号・終了番号・測点間隔（初期値100 mm＝10 cm）を指定する。
4. 「読み込んで表示」で3D・投影図・測定断面を表示する。

**欠番は番号差に応じて空けます。** 例えばu30の次がu101なら、その間隔は71×100 mm＝7,100 mmで、u31〜u100の70測点分を空白として残します。番号を詰めて配置せず、補間をオンにしても欠番はつなぎません。開始番号を0 mmとする相対位置であり、現地の絶対座標ではありません。

- 3Dには実測面と、連番の測点間に限った補間面を表示する。欠番位置には面を作らない。
- 投影図では欠番を薄い灰色の空白にする。反射強度が小さく黒く表示される実測位置とは区別する。
- 欠番の投影位置をクリックしても、右側の断面を別の測点で補わない。「データなし」と表示し、直前の実測断面を維持する。
- ファイル名末尾の英字＋番号で系列を識別する。CFGとBINが揃わない番号は欠番として残す。番号が読めない関連ファイルは対象外として件数を表示する。
- BMPがある測点は保存済みカラーテーブルと画素照合し、不一致がある場合は読込みを中止する。BMPがない場合は未照合として表示し、元BMPリンクを無効にする。
- 現在は296×432点・強度0〜254の保存断面に対応する。同じ系列内でも高さ・深さ範囲の異なるデータは自動で混ぜない。
- 一度の読込みは実測256測点・番号幅1000測点分まで。超える場合は番号範囲を狭める。
- 読み込んだデータはブラウザーのメモリー内で使用する。データの外部送信、生成データの保存、元ファイルの変更はしない。

フォルダ読込版の検証：

```powershell
node tools/check_folder_reader.cjs --all-data
```

人工データの欠番・補間を確認し、c1〜c45が旧固定データ版とバイト単位で一致すること、および手元の追加系列のBMP画素照合を確認しています。ブラウザーのフォルダ選択、iframe間のデータ受渡し、GPUの実描画の自動検証は、この作業環境では未実施です。

ユーザーによる試用を経て、このフォルダ読込版を今後の基本版とする指定を受けています。

## 社内の他の担当者が使う場合

GitHub Pagesで公開する入口は`index.html`です。公開後はChromeまたはEdgeで公開URLを開き、測定フォルダを選んで使えます。利用者によるZIPの取得・展開や追加インストールは不要です。測定データはPC内で処理し、サーバーへ送信しません。

アプリ一式をローカルに置いて使う場合は、次の手順です。

1. [app_mira](https://github.com/onochin/app_mira)の「Code」→「Download ZIP」でコード一式を取得する。[GitHubのダウンロード手順](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-source-code-archives)
2. ZIPを展開する。HTMLだけを取り出さず、`folder_reader/`と同じ位置関係で置く。
3. `MIRA_3Dフォルダ読込版.html`をChromeまたはEdgeで開く。
4. 各担当者のPCにある測定フォルダを選び、系列・番号範囲・測点間隔を指定して表示する。

利用するだけならPython、Node.js、Codex、追加ライブラリは不要です。測定データは各PCでローカル管理し、GitHubには保存しません。ZIP取得後のアプリ利用はネット接続不要です。利用者のブラウザーやGPUによる表示差は、各PCで確認してください。

非公開リポジトリから直接取得する場合はGitHub上のアクセス権が必要です。ダウンロード済みのコード一式を社内共有フォルダ等で配布する方法もあります。個人所有の非公開リポジトリでは、共同作業者への招待は書込み権限も伴うため、利用のみの担当者への渡し方とは分けて検討します。[GitHubの権限説明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/permission-levels-for-a-personal-account-repository)

### GitHub Pagesの公開設定

- 公開元は`main`ブランチのルート（`/`）。`.nojekyll`で静的ファイルをそのまま配信します。
- 公開前に`python tools/prepare_pages.py`を実行し、基本版HTMLから`index.html`を生成します。公開用入口には、ローカル生成データが必要な旧版アーカイブへのリンクを付けません。
- 公開するのはコードとドキュメントです。`data/`、`261113/`、`local_notes/`、アーカイブ内の生成データはGitの対象外です。
- `tools/github_pages.py`は開発者向けの公開操作用スクリプトです。保存済みのGit認証を使い、認証情報を表示・ファイル保存しません。アプリ利用時にはPythonを使いません。

## 今後の設定アプリの要件

- **自由回転**：3D表示をマウスでドラッグして、任意の角度から見られるようにする（「グリグリ」回す操作）。試作には回転処理を実装済みで、ブラウザー実画面での動作確認は未実施。
- **補間のオン／オフ**：試作に実装済み。初期状態はオフ。オンでは隣り合う測定断面の表示強度を線形補間し、100 mm間隔を10 mm刻みで表示する。ブラウザー実画面での動作確認は未実施。

補間オンの表示では、測定されていない断面間を推定していることが分かるようにする。補間で実際の測定分解能が向上するわけではない。

測定高さの基準（上端99 cm）、赤丸付近の見かけの位置差、複数の反射と表示条件の切り分けは、[懸案事項](docs/懸案事項.md)に記録しています。原因は未確定で、位置補正は行っていません。

## アーカイブを開く場合

[旧版一覧](archive/index.html)から、旧試作版または旧基本版バックアップをChromeまたはEdgeで開きます。旧版のHTMLと表示用ファイルの位置関係は変更しないでください。

チャット内の画像と`archive/prototype/3D_preview.png`は静止画です。回転して見るにはHTMLを開きます。

GitHubから取得したコードには測定データと生成データは含みません。旧試作版を再現するにはローカルの`261113/`を配置し、`python tools/build_probe.py`で`archive/prototype/data.js`と`verification.json`を生成してから開いてください。旧基本版バックアップには同じ2ファイルを`archive/basic/`にもローカルで配置します。元BMPへのリンクは、ルート直下の`261113/`を参照します。現在の基本版では、この事前変換は不要です。

- 3D画面を左ドラッグ：回転
- ホイール：拡大・縮小
- Shift＋ドラッグ：移動
- 「表示する強度の下限」：弱い表示強度を非表示にする
- 「不透明度」「表示する深さ」：表示範囲を確認する
- 「測定位置」：元の断面と測定位置を確認する
- 「元のBMP」：記録された機器画面を開く
- 「高さを反転」：装置の上下が仮置きと逆だった場合に切り替える
- 「断面間を補間」：測定断面のみの表示と、断面間を線形補間した表示を切り替える
- 「測点目盛り（10cm）」：3D表示と下部の投影図に、実測位置ごとの100 mm間隔の短い目盛りを表示する（初期状態はオン）

全測点への白い断面枠は、反射像に線が重なって見にくいため採用せず、短い目盛りの表示に戻しました。右側に表示中の断面だけを黄色の少し太い枠（2.5 px）で示します。目盛りを非表示にしても選択中の黄色い枠は残ります。補間をオンにしても、目盛りは全45か所の実測位置のままです。横位置の数値（mm）とc番号は表示幅に応じて間引きます。

`archive/prototype/3D_preview.png`は、旧固定データを独立したPython処理で配置・描画して確認した静止画です。

## 旧固定データ版で確認できたこと

- `.bin` は1断面296×432点、1点4バイトのリトルエンディアン整数でした。このデータの値は0〜254です。
- 各深さ行の296点を左右反転すると、BMP内の断面画像（左294、上42、幅296、高さ432）と対応します。
- 元BMPから得たカラーテーブルで45断面すべてを照合し、カーソル線を除く **5,721,525画素が完全一致**しました。
- 45×296×432＝5,754,240点の保存済み表示強度を読み込んでいます。画面の文字やカーソル線を立体化しているわけではありません。
- データは外部送信しません。元ファイルを変更しません。
- 照合の詳細と元ファイルのSHA-256は`archive/prototype/verification.json`にあります。

## 旧固定データ版の座標と未確認事項

| 項目 | 今回の扱い |
| --- | --- |
| 横位置 | c1を0 mm、c45を4,400 mm、番号順に100 mm間隔で配置 |
| 高さ | 元の断面Xを壁面の高さ方向へ配置。測定中心を0 mmとする相対座標、範囲−257〜＋257 mm |
| 深さ | 元画面・cfgに対応する0〜750 mm |

| 断面間 | オフ：100 mm間隔の45測定断面。オン：線形補間で10 mm刻みの441断面（実測45＋推定396）。測定のない隙間の形状が確定したわけではない |

## 補間表示の扱い

- 初期状態は補間オフ。オン／オフの切替えで視点・選択断面・強度下限などの設定を保ちます。
- オンでは同じ高さ・深さの隣接する値を位置に応じて線形補間します。色や、すでに投影した最大値同士を補間する処理ではありません。
- 3Dと「横位置 × 深さ」の投影に反映します。投影は補間した値から高さ方向の最大値を計算します。
- 右側の「選択した断面」と「元のBMP」は常に元の測定断面です。
- 補間断面が増えた分、3Dの不透明度を補正して見かけの濃さの増加を抑えます。
- 元ファイルは変更しません。補間した値はメモリー上で表示するだけで、外部送信・ファイル保存は行いません。基本版では欠番をまたぐ補間は行いません。

## GitHubとローカル保管の範囲

- GitHub：HTML、CSS、JavaScriptのコード、Pythonスクリプト、READMEなどのドキュメント。
- ローカルのみ：測定データ、測定データを含む生成JS、検証結果、生成プレビュー画像。
- `.gitignore`で`data/`、`261113/`、`local_notes/`、測定ファイル名のパターン、`archive/prototype/`・`archive/basic/`内の生成データと旧版プレビュー画像を除外しています。アーカイブに移動してもデータはローカル保管のままです。Gitの除外設定は、ローカルファイルを削除しません。
- 異なる名前の測定データを追加するときは、アップロード対象に含まれないかを事前に確認してください。

## 検証と旧版の再生成

```powershell
node --check folder_reader/viewer.js
node tools/check_folder_reader.cjs --all-data

# 以下は旧固定データ版を再生成・検証する場合のみ
python tools/build_probe.py
node --check archive/prototype/viewer.js
node tools/check_interpolation.cjs --real-data
python tools/render_preview.py
```

データ変換・BMP照合はPython標準ライブラリだけで動作します。静止画生成だけは、このPCにすでにあるPillowを使用しています。追加パッケージは導入していません。

`check_interpolation.cjs`は既知の人工データで補間値と投影の計算順序を確認し、`--real-data`指定時は実データで実測点の保持、切替え、視点や設定の保持も確認します。模擬DOM/WebGL APIを使用するため、GPUの実描画やGLSLコンパイルを検証するものではありません。測定データなしでも人工データのチェックは実行できます。

変換は実データの配列とBMP照合から確認したものです。`.lbv`の生波形からの再構成、`.sin`/`.cos`を用いた振幅処理は本試作の対象外です。
